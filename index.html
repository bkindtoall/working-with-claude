What I've built and kept running with Claude

Since March 2026 I've been building personal systems with Claude that run my job search, my mornings and my email. I've become quite comfortable working with AI and maintaining the agents and automations I build, mostly with Claude (Chat, Code, and Cowork) and ChatGPT (Chat and Codex), including connecting them through APIs to other software like Notion.

Claude Code wrote the code at my direction. My part has been deciding what each system should do and catching it when it went wrong. The part I enjoy most is keeping it all in order, knowing what each tool is for and whether it's still worth what it costs.

AI tool operations

The upkeep side of AI, which is the work I like best

These are personal systems with one user, so the scale is small. The upkeep they need is the same kind a team's AI tools need, and I've been doing it every week since July.

Inventory

One registry lists every automation with its purpose, schedule, model, logs and whether it should be running. A weekly check compares the list with what's actually scheduled, and anything running that isn't listed gets flagged. That check found a job that had failed for 9 straight weeks. Each job names its own model, so nothing quietly runs on a stale default.

Use cases and needs

Every new automation starts with the need it serves and a comparison of a plain script against each model size on cost and value. When I reviewed 12 niche job boards, two met the need and were adopted, and the other ten are on record with the reason each was skipped. Retired tools keep a note on why they went, so nobody rebuilds them by accident.

Adoption and usage

Every AI job logs its tokens on each run, and the weekly check reports usage by job. Usage numbers showed a nightly sync spending 690,000 tokens to save about one note. An adoption audit showed my writing corrections almost never reached the knowledge base, so I moved the capture to the moment I make them.

Access

Each job gets the least access it needs. The brief and the alerts read Gmail through a read-only token, and only the cleanup job holds write access, on its own token. Keys live in the macOS Keychain. I trimmed two permission lists that had grown to 242 and 24 one-off approvals, so each unattended task now has one exact permission.

Clean data

Status names live in one file every script reads. Stable IDs stopped duplicate listings, 25 missing application dates were backfilled and marked as estimates, and my labels are saved before any row is archived. Outdated notes get marked superseded so search stops surfacing them, and the nightly backup refuses to overwrite itself with a smaller copy.

How I work

Habits that came out of the work

Each of these started as a specific problem. They're now the rules every new automation has to follow.

Scripts first

Plain scripts handle fetching, sorting and date math. AI only gets the parts that need judgment, and the smallest model that does the job well.

Measure every run

Every job that uses AI records its tokens on each run. Before I build anything new, I compare a plain script with each model size on cost and value.

Nothing disappears quietly

Filtered jobs go to a log, my labels are saved before anything is archived, and the health check reads every error log.

The record says what I said

My career record holds only facts I've confirmed in my own words. Anything Claude inferred waits for me.

Settled stays settled

Once I decide something, it's recorded as final. New evidence gets raised once as a question, and nothing changes until I answer.

Private stays local

My records are versioned in local git with no remote. Alert texts carry a category and a count, never who sent the email.

Starting an inventory of your own

  1. List every tool and scheduled job in one place, with its purpose and whether it should be running.
  2. Write down what each one can access, and cut it to the least it needs.
  3. Log usage on every run, so cost and adoption show up as numbers.
  4. Compare the list with what's actually running each week. Anything unlisted is a finding.
  5. When something is retired, record why, so it doesn't get rebuilt by accident.
